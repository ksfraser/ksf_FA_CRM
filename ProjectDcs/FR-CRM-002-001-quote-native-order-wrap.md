# FR-CRM-002-001 — Quote wraps native FA Sales Quotation (sales_orders / ST_SALESQUOTE)

**Issue:** ksf_FA_CRM #28 (Quotes — field types)
**Related BR:** BR-CRM-03 (Quote → Order Conversion)
**Modules:** ksf_FA_CRM ↔ FA Sales (order entry, `sales/includes/db/sales_order_db.inc`)
**Status:** DESIGN (draft — no code yet)
**Traces to:** FR-CRM-002-001, issue #28

## Decision summary

Issue #28 asks to "wrap native FA's New Sales Quotation Entry
(`sales_order_entry.php?NewQuotation=Yes`)" and, failing a clean wrap, to
"convert to OOP … but ensure data is saved to native tables using native
routines where possible."

**We do NOT wrap the `sales_order_entry.php` wizard.** Research of the native
source shows it is a *session-driven multi-page UI*, not a callable form:

- `sales_order_entry.php:95` — `NewQuotation` just calls
  `create_cart(ST_SALESQUOTE, 0)`, staging lines in the `$_SESSION['Items']`
  cart.
- `sales_order_entry.php:102` / `:772` — the page renders its own
  `page()` … `end_page()` chrome, so it cannot be embedded in an AJAX tab
  controller (this is the same missing-footer failure as issue #4).
- The actual persistence is a plain DB routine:
  `add_sales_order(&$order)` in `sales/includes/db/sales_order_db.inc:13`.

**Therefore:** the CRM quote service calls the **native `add_sales_order()`
directly** (DI'd, native `db_*` only per the cross-module PDO/FA rule), and
keeps a CRM-side record that x-refs the native order. All quoting math,
numbering, tax, and persistence stay in native FA routines.

## Native primitives reused (do not re-implement)

| Requirement (#28) | Native routine / fact | Source |
|---|---|---|
| Quote # generated, not a text box | `add_sales_order()` self-assigns `order_no = get_next_trans_no($order->trans_type)` | `sales_order_db.inc:19` |
| Quote stored in native tables | `add_sales_order()` → `sales_orders` + `sales_order_details` | `sales_order_db.inc:23,61` |
| Quote is a *quotation*, not an order | `trans_type = ST_SALESQUOTE` (32); order is `ST_SALESORDER` (30) | `includes/types.inc:45-46` |

| Native lifecycle hooks fire | `add_sales_order()` calls `hook_db_prewrite()` | `sales_order_db.inc:17` |

## Functional requirements

1. **Quote record (CRM side).** `0_fa_crm_quotes` (already present) stores the
   CRM metadata and an x-ref to the native order: `native_order_no`
   (`ST_SALESQUOTE` order number) + `opportunity_id` + `contact_id` +
   `debtor_no` + approval lifecycle. Opportunity and Contact remain **CRM
   DDLs, x-ref'd separately** from the native tables (per #28).
2. **Line items.** `0_fa_crm_quote_items` maps 1:1 onto native
   `sales_order_details` (stk_code, quantity, unit_price,
   discount_percent). A resolver validates each `stk_code` against FA
   inventory; a missing item errors **per row** and does not abort the quote
   (mirrors BR-CRM-03 mapper rule).
3. **Save.** `QuotesService::save()` builds a native `$order` object and calls
   `add_sales_order()` with `trans_type = ST_SALESQUOTE`; it stores the
   returned `order_no` back onto the CRM quote. Idempotent: re-saving a quote
   with an existing `native_order_no` calls `update_sales_order()` instead of
   creating a duplicate.
4. **Calculated fields.** Subtotal, tax amount, and total are read back from
   the native order after save; the CRM columns mirror them for display. They
   are never accepted from the request body.
5. **Field types / UX (#28).**
   - Quote # → read-only display of the native `order_no` (generated).
   - Opportunity → DDL of CRM opportunities, with a "Create Opportunity"
     link opening the CRM opportunity form in a new window.
   - Contact → DDL of CRM contacts, with a "Create Contact" link opening the
     CRM contact form in a new window.
6. **Out of scope (this FR).** Quote-to-order *conversion* and the
   approval *state machine* remain BR-CRM-03; this FR only makes the quote a
   first-class native FA quotation.

## Acceptance

- A quote saved from `index.php?view=quotes` creates a row in native
  `sales_orders` with `trans_type = ST_SALESQUOTE` and matching
  `sales_order_details`; no manual re-entry in FA is required.
- The quote number is generated by FA, never typed.
- Totals equal the native order totals.
- The Opportunity and Contact DDLs are CRM-side and do not collide with
  native tables.

## Open questions (need product decision)

- Should the approval lifecycle (BR-CRM-03) gate creation of the native
  quotation, or is the native quote created immediately in `draft` and only
  *sent* after approval?
- Multi-currency: native quotes are single-currency; confirm no multi-currency
  requirement for CRM quotes.
